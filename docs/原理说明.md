# 手机 VPN 共享给电脑 —— 原理与实现

## 一、先说结论：这个功能没有任何"魔法"

Every Proxy 这类软件做的事情，本质就一句话：

> **在手机上开一个普通的 HTTP 代理服务器，监听 `0.0.0.0`（而不只是 `127.0.0.1`），
> 让同一个局域网里的电脑连上来，代替它去访问外网。**

之所以"电脑能蹭到手机的 VPN"，**不是这个软件偷了 VPN 的流量**，而是因为：

```
电脑浏览器  --(HTTP代理协议)-->  手机上的代理进程  --(普通socket)-->  目标网站
                                        ↑
                              这个进程跑在手机系统里，
                              它的 outbound 连接天然被
                              手机 VPN 的 TUN 网卡接管
```

关键点在于 **VPN 的工作层次**：

- 手机 VPN（TUN 模式）是在**网络层**接管流量的。手机上**任何**进程发起 `connect()`，
  数据包都会先进入 VPN 的虚拟网卡，被加密、转发到远端服务器。
- 手机上的代理进程，本身也是一个普通进程。它 `connect()` 出去的时候，
  走的就是 VPN 那条路。
- 所以电脑 → 手机代理 → 出网，后半段自动在 VPN 隧道里。

**换句话说：VPN 是"全局接管"，代理服务器只是"对外的一个入口"。**
这跟你在电脑上跑 Clash、然后手机连电脑的代理，是完全对称的一件事。

## 二、Every Proxy 的四个功能分别是什么

| 功能 | 作用 | 电脑怎么用 |
|---|---|---|
| **HTTP Proxy** | 标准 HTTP/HTTPS 代理（支持 CONNECT 隧道） | 系统代理填 `手机IP:端口` |
| **SOCKS Proxy** | SOCKS5 代理，支持任意 TCP/UDP | 软件里填 SOCKS5 `手机IP:端口` |
| **PAC Server** | 提供一个 `/proxy.pac` 脚本，告诉客户端"什么流量走代理、什么直连" | 系统代理填 `http://手机IP:端口/proxy.pac` |
| **HTTP/SOCKS 开关** | 决定监听哪些协议、哪个端口 | — |

### PAC 到底是什么

PAC（Proxy Auto-Config）就是一个 JavaScript 文件，里面必须有一个函数：

```javascript
function FindProxyForURL(url, host) {
    return "SOCKS5 192.168.43.1:1080; PROXY 192.168.43.1:8080; DIRECT";
}
```

浏览器每次发请求前都会调用它，返回值决定怎么走：

- `SOCKS5 ip:port` —— 走 SOCKS5 代理
- `PROXY ip:port` —— 走 HTTP 代理
- `DIRECT` —— 直连，不走代理
- 用 `;` 分隔表示**依次尝试**（前一个失败就试下一个）

Every Proxy 的 PAC 内容基本就是一行"全走代理，失败直连"。
它之所以有用，是因为**手机 IP 会变**（换热点就变），
用 PAC URL 的话客户端会自动去拉最新脚本，不用你手动改 IP。

## 三、源码印证

我扒了 GitHub 上一个复刻版（`lahuman/everyProxyCore`，Kotlin 写的 Android 项目），
它的结构和 Every Proxy 完全一致：

```
proxy/HttpProxyServer.kt    <- HTTP/HTTPS 代理，含 CONNECT 处理
proxy/SocksProxyServer.kt   <- SOCKS5 代理
proxy/PacServer.kt          <- PAC 文件 HTTP 服务，路径 /proxy.pac
proxy/PacFile.kt            <- PAC 脚本生成器
proxy/TcpRelay.kt           <- 双向数据搬运（32KB 缓冲，两个线程对拷）
proxy/SocketConnector.kt    <- 出站连接
```

最有说服力的一行在这里 —— `SocketConnector.kt`：

```kotlin
object DirectSocketConnector : SocketConnector {
    override fun connect(host: String, port: Int): Socket {
        val socket = Socket()
        socket.tcpNoDelay = true
        socket.connect(InetSocketAddress(host, port), 15_000)
        return socket
    }
}
```

**它就是一个最普通的 `java.net.Socket`，没有绑定任何 VPN 接口、没有任何特殊处理。**

这就直接证明了：不需要特殊操作，手机进程的普通出站连接会自动走 VPN。
（前提是 VPN 是"全局模式"而不是分应用模式；如果是分应用模式，
就要把代理软件本身也勾进 VPN 的应用列表里。）

`PacFile.kt` 生成的内容也很直白：

```kotlin
val chain = buildList {
    if (config.socksEnabled) add("SOCKS5 $host:${config.socksPort}")
    if (config.httpEnabled)  add("PROXY $host:${config.httpPort}")
    add("DIRECT")
}.joinToString("; ")
```

跟上面我讲的一模一样。

## 五、你实际可用的方案

### 手机端（零编译）

用 **Termux** 跑我写的 `vpnshare.sh`。它做的事和 Every Proxy 一样，
而且是我实测过的（PAC / HTTP / CONNECT / SOCKS5 四项全部跑通）。

```bash
# 1. 装 Termux（F-Droid 或 GitHub 下载，别用 Play 商店那个老版本）
# 2. 装 Python
pkg update -y && pkg install -y python

# 3. 把 vpnshare.sh 放到手机任意目录，然后
bash vpnshare.sh
```

启动后会打印：

```
HTTP 代理 : http://192.168.43.1:8080
SOCKS5    : 192.168.43.1:1080
PAC 脚本  : http://192.168.43.1:8080/proxy.pac
```

### 电脑端（Windows，双击即用）

```
vpn-share/pc/
  ├── 一键启动-共享VPN.bat    <- 双击这个
  ├── 扫描手机代理.bat        <- 只看不设置
  ├── 还原代理.bat            <- 手动还原
  └── Start-VpnShare.ps1      <- 主脚本
```

`一键启动-共享VPN.bat` 会自动：

1. 提权到管理员
2. 扫描局域网找到手机的代理端口
3. 备份你原来的代理设置
4. 把系统代理指过去（同时设 PAC 和手动代理）
5. 保持生效，**关窗口就自动还原**

也可以手动指定，速度最快：

```powershell
.\Start-VpnShare.ps1 -ProxyHost 192.168.43.1 -ProxyPort 8080
```

## 六、必须知道的三个坑

1. **热点要支持设备互访。**
   有些手机的热点默认"客户端隔离"，电脑根本 ping 不通手机。
   如果扫不到代理，先 `ping 手机IP` 试试。

2. **VPN 必须是全局模式。**
   如果 VPN 是"分应用代理"，把 Termux / 代理软件本身加进白名单，
   否则代理进程的出口不走隧道，电脑就上不了外网。

3. **电脑上要关掉其他代理软件。**
   Clash、v2rayN 之类如果占着系统代理，会跟我这个脚本打架。
   先退出它们再跑脚本。

## 七、为什么"手动填 IP 和端口"能工作而"自动发现"有时不行

因为手机 IP 是**动态分配**的：

- 手机开热点时，手机自己通常是网关，IP 一般是 `192.168.43.1`（Android 常见）
  或 `172.20.10.1`（iPhone）。
- 手机连别人的 WiFi 时，IP 就是路由器分配的，比如 `192.168.1.37`，
  换个网络就变了。

所以 Every Proxy 给你 PAC URL 是很聪明的做法：
客户端记住的是 `http://xxx/proxy.pac`，实际 IP 由脚本内容决定。
但 PAС 里**还是写死了 IP**，所以换网络照样要重新配置。

我的脚本做的事就是：**自动帮你把这个动态 IP 找出来。**
